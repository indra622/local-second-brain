# 명령과 지원 범위

[English](reference.md) | **한국어**

## 설치 전 준비 사항

**기존 지식을 읽기만 할 때:** 파일 탐색기와 UTF-8 텍스트 또는 Markdown 편집기면 된다.
파일 열람에는 Python, CLI, AI 계정이나 Obsidian이 필요 없다.

**CLI를 설치하고 실행할 때:**

- **운영체제:** macOS 또는 Linux의 로컬 POSIX 파일시스템. 호스팅된 macOS와 Ubuntu에서 CI를 통과했으며 다른 Linux 환경은 별도로 검증하지 않았다.
  Windows는 POSIX 전용 파일 API 때문에 지원하지 않는다. WSL도 미검증이다.
- **Python:** 표준 `venv` 모듈을 사용할 수 있는 Python 3.11 이상. CI는 Python 3.11과 3.14를 검사하며 로컬 검증은 3.14.6에서 했다.
- **터미널:** 아래 예제를 실행할 bash, zsh 같은 POSIX 셸.
- **프로젝트 소스:** `pyproject.toml`이 포함된 로컬 프로젝트. 압축파일이나 복사본이 있으면 Git은 필수가 아니다.
- **설치 도구와 의존성:** 가상환경 안의 `pip`가 PyYAML과 빌드 도구를 설치한다.
  설치 시 패키지 다운로드에는 보통 인터넷이 필요하지만, CLI 동작에는 필요 없다.
- **저장 공간:** 쓰기 가능한 로컬 폴더. `init`에는 새 경로나 빈 폴더를 지정한다.
  지식 폴더는 프로젝트 코드나 `.venv` 밖에 따로 두는 것이 좋다.

먼저 Python을 확인한다.

```sh
python3 --version
python3 -m venv --help > /dev/null
```

버전이 3.11보다 낮으면 아래 명령의 `python3`를 새 Python 실행 경로로 바꾼다.
`venv`가 없으면 운영체제의 Python venv 지원 패키지를 먼저 설치한다.
GPU, DB, 서버, API 키, Obsidian 플러그인이나 특정 AI 서비스는 필요 없다.
본문은 직접 써도 되고, 원하는 에이전트로 정리해도 된다.

## 명령과 파일

| 명령 | 동작 |
| --- | --- |
| `init BUNDLE` | 새 경로나 빈 디렉터리에 `index.md`를 만든다. 비어 있지 않으면 거부한다. |
| `capture BUNDLE FILE --id ID --actor ACTOR --resource ORIGIN` | 원문 바이트와 출처, 수집 주체, 시간, SHA-256을 보존한다. ID 재사용을 거부한다. |
| `curate BUNDLE ID --body FILE --source SOURCE_ID --actor ACTOR` | 준비한 UTF-8 본문을 새 개념 리비전으로 저장한다. `--source`는 반복할 수 있다. |
| `review BUNDLE ID --revision rNNNNNN --actor ACTOR --evidence RESOURCE` | 현재 본문을 유지한 새 리비전에 검토 선언을 덧붙인다. |
| `recall BUNDLE QUERY` | 인덱스의 현재 맥락을 크기 제한과 검색 진단을 담은 JSON으로 읽는다. |
| `search BUNDLE QUERY` | 모든 개념 리비전의 제목과 본문을 단어로 검색한다. |
| `list BUNDLE` | 모든 CLI 리비전 요약을 경로순으로 표시한다. |
| `show BUNDLE ID [--revision rNNNNNN]` | 현재 리비전 또는 지정한 리비전의 본문을 읽는다. |
| `history BUNDLE ID` | 리비전 요약을 오래된 순서로 표시한다. |
| `diff BUNDLE ID BEFORE AFTER` | 두 리비전의 메타데이터와 본문을 비교한다. |
| `check BUNDLE` | 메타데이터 일부를 검사하고 링크 경고와 오래된 문서를 별도로 보고한다. |

ID는 영문 소문자나 숫자로 시작하는 1~64자의 영문 소문자, 숫자, 하이픈이다.
`curate`는 `--type`, `--title`, `--status`, `--stale-after`도 받는다.
새 `curate`의 title, type, actor와 `capture`의 actor는 Python 함수에서도 한 줄 문자열이어야 한다.
LF, CR, CRLF, 수직 탭, form feed, 파일/그룹/레코드 구분자, NEL, Unicode 줄/문단 구분자는
쓰기나 요청 예약 전에 `invalid_input`으로 거부한다. 일반 공백과 한글/영문은 허용한다.
가져온 과거 메타데이터의 여러 줄 필드는 이 입력 제한으로 거부하지 않는다.

Frontmatter 구분자는 들여쓰기 없는 정확한 `---` 줄이며 LF 또는 CRLF를 쓴다.
파일 끝의 닫는 `---`도 허용한다. 공백, 단독 CR이나 Unicode 줄 구분자는 경계로 보지 않는다.
유효한 YAML 값 안의 들여쓴 구분자는 메타데이터로, 본문의 구분선은 본문으로 남긴다.
리비전을 만들기 전에 직렬화한 UTF-8을 다시 파싱하고 검사하여 본문 전체와 메타데이터 의미를 확인한다.
curate/review는 요청 예약 전에 이 바이트를 준비한다. 검사 실패는 리비전, 인덱스 변경이나
미완료 요청을 남기지 않으며 기존 파일을 자동으로 고치지 않는다.

`curate`는 원문을 직접 해석하거나 준비한 글의 사실을 확인하지 않는다.
명시적 `review`만 `verified`를 덧붙이며 형식 검사는 검토 기록을 만들지 않는다.
본문의 상대 링크는 준비 파일 위치가 아닌 최종 리비전 위치를 기준으로 쓴다.

```text
wiki/
  index.md
  sources/garden-note/
    content.raw
    provenance.json
  concepts/garden/
    r000001.md
    r000002.md
    r000003.md
```

원문은 확장자나 인코딩에 관계없이 바이트 그대로 저장한다. 줄바꿈과 BOM도 바꾸지 않는다.
원문 Markdown도 `.raw`로 보존하므로 개념 문서로 잘못 검사하지 않는다.
원문 검색, PDF 추출, 인코딩 추측은 없다. 본문과 개념 문서는 UTF-8이어야 한다.
다른 인코딩은 에이전트가 별도 작업 파일에서 변환하고 원문과 구분해야 한다.

`list`, `show`, `history`, `diff`는 파일을 바꾸지 않는 열람 명령이다.
`concepts/ID/r000001.md`부터 `r999999.md`까지의 CLI 파일을 대상으로 한다.
리비전 인자는 정확히 `rNNNNNN` 형식이며 ID 규칙은 `curate`와 같다.
`show`는 가장 큰 번호를 현재 버전으로 추측하지 않는다. 현재 인덱스가 없으면 `--revision`을 지정한다.
요약에는 현재 표시, 상태, 검토 수준, 신선도와 메타데이터 오류가 들어간다. `show`는 전체 본문과 메타데이터도 보여 준다.
`diff`는 메타데이터를 포함한 전체 Markdown의 unified diff를 앞뒤 세 줄과 함께 출력한다.
동일한 리비전이면 JSON의 `diff`는 빈 문자열이고 텍스트는 `No differences.`다.
가져온 일반 OKF 노트는 검색, 검사와 편집기로 읽을 수 있지만 이 명령들이 리비전 이력을 추론하지는 않는다.
없는 개념이나 리비전, 안전하지 않은 경로는 종료 코드 `2`다.
잘못된 메타데이터는 `metadata_errors` 또는 텍스트의 오류 표시로 알리고 읽을 수 있는 내용은 반환한다.
UTF-8이 아니면 오류와 빈 본문을 반환한다. `diff`는 잘못된 노트를 거부한다.
YAML 매핑의 문자열이 아닌 키는 출력할 때만 문자열로 바꾸며 저장된 노트는 바꾸지 않는다.
변환한 키가 충돌하거나 값이 순환하면 데이터를 버리지 않고 명시적 오류를 반환한다.
읽기 명령의 실행 오류는 JSON 모드에서 stderr의 `{"error": "..."}`, 텍스트 모드에서
`second-brain:` 메시지로 출력한다. 인자 문법 오류는 argparse의 텍스트 진단을 사용한다.

`review`는 잠금 안에서 인덱스가 가리키는 정확한 현재 리비전만 받으며 과거 대상은 거부한다.
actor는 `human:ID`, `process:ID`, `PRODUCER/VERSION` 중 하나다. 구성요소는 비어 있지 않아야 하며
공백, 제어 문자, 콜론, 슬래시나 역슬래시를 포함할 수 없다. 이는 신원 인증이 아닌 선언이다.
기록 시 CLI가 관측한 UTC 오프셋 포함 시각을 사용하며 과거 검토 시각은 입력할 수 없다.
근거는 호스트가 있는 절대 HTTP(S) URL 또는 번들 루트 기준으로 실제 존재하는 비어 있지 않은
일반 파일이다. 로컬 경로의 앞 `/`는 생략할 수 있고 파일명 공백은 허용한다.
URL 자격 증명, 잘못된 포트, escape, 공백, 다른 scheme, 로컬 query 또는 fragment, 경로 순회,
역슬래시, 앱 디렉터리와 심볼릭 링크는 거부한다. URL에 접속하거나 근거를 실행하지 않는다.
근거 참조는 선언이며 진실의 증거가 아니다.

새 이벤트는 표준 OKF `by`/`at`와 프로젝트 확장 `x-second-brain-target` 및
`x-second-brain-evidence`를 사용한다. 대상에는 `resource`와 전체 파일 바이트의 SHA-256,
근거에는 `resource`와 로컬 파일일 때만 SHA-256을 기록한다. 해시는 바이트를 식별하며 신원을
인증하지 않는다. 원본 파일 바이트는 유지한다. 새 파일의 본문, 알 수 없는 YAML 키와 원래
생성 기록을 포함한 메타데이터 값도 유지하되 YAML 서식은 달라질 수 있다.
기존 검토 매핑이나 목록은 항목을 보존한 목록이 된다. 상태는 바꾸지 않으며 이후 `curate`는
검토 기록을 물려받지 않는다. 상세 규칙과 실패 한계는 한영 [검토 규칙](review-contract.md)을 참고한다.

검색은 Unicode `\w+` 토큰을 `casefold`한 뒤 모든 검색어가 정확히 있는 문서를 찾는다.
점수는 중복을 제거한 검색어의 출현 횟수 합이며, 점수 내림차순과 경로 오름차순으로 정렬한다.
형태소 분석, 부분 문자열 검색, 의미 검색은 없다. 기본 검색은 이전 리비전도 포함하며 기존 JSON 키와 점수를 유지한다.
`title`과 `snippet`이 추가된다. `snippet`은 본문 공백을 한 칸으로 합친 뒤 앞에서 최대 160 Unicode 문자를
보여 준다. 잘린 경우 마지막 문자는 `…`다.

`--current-only`는 인덱스가 가리키는 현재 리비전만 남기며, 현재 여부를 모르면 제외한다.
`--status draft|stable|deprecated`는 상태로 필터링하고 메타데이터 오류가 있는 문서는 제외한다.
유효한 OKF 노트에서 상태가 생략되면 기존처럼 `stable`이다.
`--freshness fresh|stale|unknown`은 `stale_after`만 사용한다. 유효한 기한이 `--now`보다 뒤면 fresh,
기한에 도달했으면 stale이다. 기한이 없거나 잘못되었거나 UTC 오프셋이 없으면 unknown이다.
다른 메타데이터 오류는 그대로 표시하되 신선도를 바꾸지 않는다. 필터는 AND로 결합하며 리비전마다 적용한다.
이전 리비전이 조건에 맞아도 현재 리비전을 대신하지 않는다.
재현 가능한 시간 판정에는 `--now`, 읽기 쉬운 Unicode 출력에는 `--format text`를 쓴다.
`current`는 이 CLI의 현재 링크 여부이며, 가져온 일반 번들에서 판단할 수 없으면 `null`이다.
`status`, `trust`, `stale`, 생성과 검토 기록, 메타데이터 오류를 함께 출력한다.
`stale: null`은 기한이 없거나 잘못되어 판단할 수 없다는 뜻이다. 검토 수준은 기록에서
계산한 참고 정보다. CLI가 사실이나 검토자의 신원을 확인했다는 뜻이 아니다.

검사는 `.obsidian`과 `.git`을 제외한 번들 안의 `.md`를 읽는다. `index.md`와 `log.md`는 예약 파일로 구분한다.
깨진 링크와 오래된 문서는 형식 오류와 별도이며, 이것만 있으면 종료 코드는 0이다.
메타데이터 오류가 있으면 1, 입출력 실패나 안전상 거부, 잘못된 인자는 2다.
정확한 검사 범위와 생략한 항목은 [검사 범위](okf-subset.md)에 적었다.

## 크기를 제한한 현재 회상

`recall BUNDLE QUERY [--match auto|exact|lexical] [--limit N] [--max-chars N] [--now TIME]`
은 읽기 전용이며 JSON만 출력한다. `--format`은 받지 않는다. 기존 명령의 출력 형식은 유지한다.
인덱스가 지정한 CLI 리비전만 읽으며 가장 큰 번호나 과거 버전으로 대신하지 않는다.
가져온 일반 노트는 기존 search/check로 확인한다.

기본 `auto`는 `casefold`한 Unicode `\w+` 단어가 모두 정확히 일치하는 노트를 찾는다.
현재 정확한 결과가 하나도 없을 때만 lexical로 다시 찾는다. `exact`는 확장하지 않는다.
`lexical`은 검색어가 3 코드 포인트 이상이거나 완성형 한글 음절(`가`..`힣`)만으로 된
2글자 이상이면 노트 단어의 앞부분과 비교하고, 그보다 짧으면 정확히 비교한다.
모든 검색 단어가 제목이나 본문에 있어야 한다. 점수는 각 검색어에 맞는 단어의 출현 횟수 합이며,
같은 점수는 경로순이다. 형태소, 의미 검색, Unicode 정규화나 원문 검색은 없다.
lexical에서 `rename`은 `renames`, `보고서`는 `보고서를`과 맞는다.
`xrename`, `중간보고서`는 맞지 않는다. `port`가 관계없는 `portable`과 맞을 수 있으므로
결과의 관련성은 판단해야 한다. `규칙`/`결정`은 `규칙을`/`결정을`과 맞지만 관계없는
`규칙성`/`결정체`도 찾을 수 있다. `불규칙한`/`미결정`은 맞지 않으며 한 음절은 확장하지 않는다. 정확한 결과가 있으면 다른 접두어 후보는 생략한다.
필요하면 `--match lexical`을 명시한다.

결과 제한은 기본 5개, 범위 1..100이다. 문자 예산은 기본 12000, 범위 2048..1000000이다.
`--max-chars`는 JSON 문법, escape, 진단과 마지막 줄바꿈을 포함한 **성공 stdout 전체**를
Python Unicode 코드 포인트 수로 제한한다. 바이트, 글자 묶음이나 토큰 수가 아니다. YAML escape에서 나온 surrogate 코드 포인트는
JSON `\uXXXX`로 출력하고 6자를 예산에 포함한다. 한글 등 유효한 Unicode는 그대로 표시한다.
본문을 줄이고 그래도 맞지 않으면 결과를 생략하므로 요청한 개수보다 적게 나올 수 있다.
`matched`는 제한 전 일치 수, `omitted_results`는 반환하지 못한 수다.
`id`, `revision`, `path`로 정확한 `show` 대상을 지정한다. `body_start`, `body_end`는 원래
본문의 코드 포인트 위치이고 `body_chars`는 전체 본문 길이다. 첫 본문 일치 단어보다 최대 120자
앞에서 시작하여 최대 1600자를 고른 뒤 예산에 맞게 줄인다. 모든 검색어를 담는다는 보장은 없다.
`body_truncated`는 본문 생략을 표시한다.

제목, 상태, 검토 수준, 신선도와 기한, 메타데이터 오류, 생성과 검토 선언 및 출처 참조를 고른다.
중첩 선언에서는 `id`, `resource`, `last_modified`, `by`, `at`, `sha256`, 검토 대상과 근거 필드만
고른다. 문자열은 240자, 목록은 8개, 중첩은 4단계로 제한한다.
`selected_fields_truncated_or_omitted`는 이 제한에 따른 축소를 표시한다. YAML의 NaN이나
무한대는 JSON `null`로 바꾸고 이 표시를 켜며 메타데이터 오류도 유지한다.
전체 메타데이터와 알 수 없는 확장 필드는 생략하므로 `metadata_omitted`는 항상 true다.
전체 근거는 `show`로 확인한다. 잘린 참조는 전체 경로로 쓸 수 없다. 출처 참조는 검증하지 않은
선언이며 경로를 해석하거나 접속, 인증, 실행하지 않는다. 파일 접근은 별도 작업 권한을 따르고
지원되는 링크 검사는 `check`로 한다. draft, deprecated, stale, unverified나 잘못된 메타데이터도
일치하면 드러낸다. 검토 수준은 인증되지 않은 기록에서 계산한다. `stale: null`은 판단 불가다.

`requested_match`, `match_mode`, `fallback_used`를 먼저 읽는다.
`state`는 `matches`, `no_match`, `empty_index`, `invalid_index`, `partial`(일치와 제외가 함께 있음),
`incomplete`(일치 없이 제외가 있음), `budget_omitted`(일치하지만 모두 예산으로 생략)를 구분한다.
제외 수는 읽을 수 없거나 안전하지 않은 리비전, 지원하지 않는 리비전, UTF-8 오류를 구분한다.
`invalid_metadata_notes`는 검색에 맞지 않은 노트도 포함한 메타데이터 오류 노트 수다.
잘못된 인덱스를 과거 리비전으로 대신하지 않는다. 실패가 지식 부재의 증명은 아니며 진단 안내를 따른다.
상태 결과는 종료 0, 입출력이나 인자 오류는 2다. 실행 오류는 stderr JSON, argparse 문법 오류는
텍스트다. 예산은 stderr, 입력 크기, 파싱 메모리나 실행 시간을 제한하지 않는다.
읽기에는 스냅샷 잠금이 없으므로 검사 중 파일을 동시에 편집하지 않는다.

## 에이전트 오류와 쓰기 요청

모든 명령에서 전역 `--error-format json`을 **명령 앞에** 둘 수 있다. `--error-format=json`도
가능하다. stderr의 실패만 바꾸며 argparse 오류도 JSON으로 출력한다. 성공 stdout과 종료 코드는
유지한다. 명령 앞에서 반복하면 마지막 `json` 또는 `legacy`가 파서와 실행 오류에 함께 적용된다.
명령 뒤에는 둘 수 없다. 기본 legacy는 기존 오류 형식과 메시지를 유지한다. 도움말은 텍스트다.
실패는 종료 2다. check의 메타데이터 오류 보고는 기존 stdout과 종료 1을 유지한다.

stderr는 ASCII escape를 쓴 엄격한 JSON 객체 하나다.

```json
{"error":{"code":"precondition_failed","message":"...","message_truncated":false,"action":"reread_then_new_request"}}
```

message는 최대 1000 코드 포인트의 설명이며 제어 흐름에는 메시지 대신 code를 쓴다.
잘못된 Unicode도 escape로 출력한다. 예외 메시지의 NaN이나 무한대는 문자열이다.
예상 밖의 예외는 이 모드에서 traceback 없이 internal_error로 출력한다. action은 재시도 안전성의 보장이 아니다.

| code | 대응 |
| --- | --- |
| `arguments` | 명령 문법을 고친다. |
| `invalid_input` | ID, 메타데이터, 검색어, 시각 등 입력을 고친다. |
| `invalid_index` | 없거나 잘못된 현재 인덱스를 검사한다. |
| `not_found` | 입력 파일이나 개념/리비전이 있는지 확인한다. |
| `already_exists` | 기존 대상을 검사하며 덮어쓰지 않는다. |
| `unsafe_path` | 거부된 경로, 심볼릭 링크나 일반 파일이 아닌 대상을 검사한다. |
| `locked` | 실제 작성자가 끝나기를 기다리거나 남겨진 잠금을 검사한다. 무작정 삭제하지 않는다. |
| `precondition_failed` | 현재 내용을 다시 읽고 판단한 뒤 새 요청을 허용한다. |
| `request_conflict` | 원래 입력을 복원하거나 별도의 새 작업인지 판단한다. |
| `recovery_required` | 멈추고 요청 기록과 번들을 검사하며 무작정 재실행하지 않는다. |
| `concurrent_change` | 외부 편집으로 미연결 리비전이 남았을 수 있으므로 멈추고 검사한다. |
| `io_error` | 입출력과 부분 기록 가능성을 검사한다. |
| `internal_error` | 예상 밖 실패이므로 멈추고 검사한다. |

### 요청 동일성과 현재 리비전 조건

capture, curate, review는 선택적으로 `--request-id ID`를 받는다. ID는 영문 소문자나 숫자로
시작하는 1~64자의 영문 소문자, 숫자, 하이픈이며 **한 번들 안의 세 명령 전체**에서 구분한다.
허용된 작업마다 새 ID와 원래 입력을 실행 전에 저장한다. ID를 생략하면 기존 쓰기 방식이다.
같은 본문의 일반 curate도 새 리비전을 만든다. 검토 선언은 신원 인증이 아니다.

curate의 `--expect-current rNNNNNN`은 인덱스가 정확히 그 리비전을 가리킬 것을 요구한다.
`absent`는 그 개념의 현재 인덱스 항목이 없음을 뜻하며 과거 파일이나 미연결 파일이 없다는 뜻은 아니다.
생략하면 일반 curate다. review의 `--revision` 조건은 유지한다. 인덱스 읽기, 요청 조회, 조건 비교와
변경은 같은 쓰기 잠금 안에서 한다. 다른 작성자가 잠금을 보유하면 내부에서 기다리지 않고 거부한다.

동일한 완료 요청은 현재 리비전 조건을 검사하기 전에 원래 성공 결과를 반환한다. 현재가 더 진행되어도
출처, provenance, 리비전이나 검토를 추가하지 않고 인덱스를 되돌리지 않는다. 같은 ID의 명령이나
입력이 바뀌면 request_conflict다. 자동으로 생성한 수집/생성/검토 시각은 동일성에서 제외한다.
지문에는 다음을 포함한다.

- Capture: 원문 바이트 SHA-256, provenance에 저장하는 원래 파일명, 출처 ID, actor와 origin.
- Curate: 준비 본문 바이트 SHA-256, 순서가 있는 출처 ID와 원문/provenance 해시, 개념 ID,
  actor, type, 실제 title, status, stale-after 인자와 expect-current 인자.
- Review: 정확한 대상 리비전 바이트 해시, 개념/리비전, actor, 입력한 evidence와 해석한 근거 참조.
  로컬 근거는 바이트 해시를 포함한다. URL은 접속하지 않은 선언이다.

파일 경로만으로 요청을 구분하지 않는다. 같은 바이트의 준비 본문을 다른 경로로 옮겨도 된다.
capture의 원래 파일명 변경은 다르다. 재실행 때도 원래 입력, 출처 파일, 검토 대상과 근거를 읽어
지문을 계산하므로 그대로 보존해야 한다. 입력이 없거나 잘못되면 요청 조회 전에 실패할 수 있다.
관리 인덱스도 읽을 수 있어야 한다. title 기본값은 실제 값으로 비교하며 출처 순서, 기한/근거 인자는
정확히 유지한다. 재시도하면서 expect-current를 최신 값으로 바꾸지 않는다.
새 결정이면 현재 내용을 다시 읽고 판단한 뒤 새 요청 ID와 입력을 저장한다.

### 요청 기록과 실패 한계

생성 전용 기록은 예약된 루트 `.lkw-requests/ID/intent.json`, `result.json`에 둔다.
이 루트 경로는 일반 노트 나열/검색/검사에서 제외하지만 요청 접근에는 descriptor 기반 일반 파일 및
심볼릭 링크 거부 규칙을 적용한다. 이곳에 지식을 저장하거나 검토 근거로 쓰지 않는다.
재시도를 위해 기록을 고치거나 삭제하지 않는다. 버전, 명령/지문, JSON 결과, 결과 checksum과
생성 파일 SHA-256을 저장한다. 재실행은 기록 형식/checksum과 생성한 원문/provenance 또는
리비전 바이트를 확인한다. 해당 리비전이 아직 현재일 필요는 없다. 로컬 무결성 검사이며 인증이나
의도적인 변조 방지는 아니다.

가능한 검증과 현재 조건 거부는 예약 전에 한다. 요청 폴더를 예약한 뒤 intent를 생성하고 동기화한다.
그 뒤 실제 변경을 하고 생성 파일을 읽은 후에만 result를 만든다. 이미 있는 요청 폴더에 온전한
일치 완료 기록이 없으면 실행하지 않는다. 예약 이후 실패는 보수적으로 recovery_required다.
아무 지식도 바뀌지 않았거나, 출처 폴더만 있거나, 원문만 있거나, 수집이 완료되었거나,
미연결 리비전 또는 이미 현재로 선택된 리비전이 남을 수 있다. result 쓰기 실패는 부분 기록을 남긴다.
마지막 동기화가 실패했어도 온전한 결과와 생성 파일이 남아 있으면 재실행이 관측된 성공을 확인하고
추가 쓰기 없이 반환할 수 있다.

종료 2를 rollback이나 재시도 가능의 뜻으로 읽지 않는다. 잘못되거나 미완료인 요청을 새 ID로 우회하지
않는다. 요청 폴더, 원문, 리비전, 인덱스와 잠금을 사람이 검사한다. 복구나 기록/잠금 삭제 명령은 없다.
잠금 경합 자체는 요청을 예약하지 않는다. 기존 ID 없는 쓰기도 부분 기록을 남길 수 있다.
요청 JSON 읽기/쓰기는 8 MB로 제한하며 큰 검토 기록은 가능한 한 미리 거부한다.
예상보다 큰 완료 기록은 미완료 요청을 남길 수 있다. 완전한 트랜잭션, 자동 조정, crash rollback이나
정전 후 복구는 보장하지 않는다. 편집기는 잠금을 따르지 않으므로 동시에 편집하지 않는다.
입력 파싱과 해시는 메모리에서 처리하며 파일 접근과 검토 권한은 외부 작업 지시를 따른다.

## 에이전트와 저장 한계

[에이전트 사용 안내와 작업 템플릿](agent-kit.ko.md)부터 읽고
[한국어 작업 절차](../workflows/AGENT-WORKFLOW.ko.md)와
[본문 템플릿](../templates/concept-body.ko.md)을 에이전트에 전달한다. 각각 영어 문서도 있다.
기존 [합성 예제 번들](../examples/bundle/index.md)은 한국어다.
지침과 템플릿은 번들 밖에 둔다. 특정 vault 구조나 에이전트 설정을 가정하지 않는다.

쓰기 명령은 번들의 배타 잠금을 사용하며 파일 생성 시 기존 파일을 덮어쓰지 않는다.
`index.md`의 관리 표식 사이에는 생성된 현재 링크만 둔다. 그 밖에 쓴 글은 보존한다.
관리 구역의 구조를 바꾸면 `curate`는 거부한다. 파일을 직접 편집하는 프로그램은 잠금을
따르지 않으므로 쓰기 명령과 동시에 편집하지 않는다. 장애 후 남은 잠금이나 미연결
리비전은 자동 삭제하지 않는다. [구조와 복구 범위](architecture.md)를 먼저 확인한다.

웹 UI, 서버, 벡터 DB, 클라우드, MCP, 계산 실행과 attestation은 이번 범위에 없다.
PyPI 배포는 아직 없으므로 프로젝트 소스로 설치한다.
