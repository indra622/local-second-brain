# 다른 에이전트에서도 이어지는 지식 정리

[English](knowledge-practice.md) | **한국어**

Local Second Brain은 좋은 지식 정리 경험을 다른 사람과 에이전트에게도 옮길 수 있어야 한다.
자연스럽게 말한 생각의 원문을 남기고, 의미를 정리하고, 근거 있는 지식과 연결하고, 나중에
다시 쓰고, 생각이 바뀌면 이전 기록을 보존하며 고친다. 안전한 저장은 이를 받치는 기반이다.
파일 저장이나 프로젝트 인계만으로 제품 목표를 다했다고 보지 않는다.

이 문서는 issue68의 경험/수용 기준이며 새 설정 프로필이나 정리 키트가 이미 있다는 주장이
아니다. 명령, 권한, 재시도/CAS, 중단의 운영 정본은 [기존 절차](../workflows/AGENT-WORKFLOW.ko.md)다.

## 사용자가 할 수 있어야 하는 일

- “이 독서 성찰을 내 지식 폴더에 남겨 줘. 원문도 보존하고 내가 고민하는 의미를 정리해 줘.”
  허가된 외부 에이전트가 명령과 ID 처리를 맡는다.
- “앞의 생각과 이어질 수도 있어. 유용한 연결인지 봐 줘.” 범위 안에서 찾아 근거를 읽고
  연결 이유를 설명하거나 관련 없음/못 찾음을 정직하게 알린다. 모든 노트에 edge가 필요하지 않다.
- “그 생각의 일부를 바꾸고 싶어.” 새 원문을 남기고 관련 노트를 수정하되 과거 원문과 노트를 지우지 않는다.
- 새 세션에서 “내 생각이 어떻게 바뀌었고 이번 질문에 무엇이 중요하지?”라고 묻는다.
  과거 대화를 몰라도 저장한 정확한 근거와 현재/이전 버전을 구분해 답하며 일반 조언으로 대신하지 않는다.

## 제품 원칙

**권한이 있을 때 저장한다.** 명시한 저장 요청 또는 사용자가 켠 범위 있는 트리거만 저장을
시작한다. 설치나 일반 질문, 한 폴더 접근이 모든 대화 저장, 이웃 폴더 탐색, 다른 제공자 사용의
동의가 아니다. 트리거는 대상 자료, 목적지, 해제 방법을 밝혀야 한다. 명시한 저장 금지는 그 차례의 활성 트리거보다
우선하며 구현은69에서 다룬다.

**해석 전에 원문을 보존한다.** 파일이면 BOM/줄바꿈을 포함한 바이트와 출처 기록을 보존하고
정리 노트가 source ID를 가리킨다. 채팅이면 호스트가 실제 제공한 텍스트와 export/정규화 경계를
밝혀 접근하지 못한 원채널 바이트까지 보존했다고 주장하지 않는다. 새 해석은 원문을 덮어쓰지
않는다. 수집된 출처도 내용의 진실을 증명하지 않는다.

**문장 순서가 아니라 의미를 정리한다.** 사용자의 질문, 이유, 긴장, 예시, 불확실성을 살펴 무엇을
생각하고 언제 적용하는지 설명한다. 짧은 전사, 기계적 추출이나 문장 재배열만으로는 부족하다.
출처의 주장, 사용자의 생각, 에이전트 해석, 미검증 추론을 구분한다. “그럴 수도”를 확정 규칙으로
바꾸거나 책/사용자가 하지 않은 말을 만들지 않는다. 사용자가 해석을 읽고 고칠 수 있어야 하며
actor 표기를 인증된 승인으로 보지 않는다.

**연결은 선별한다.** 그럴듯한 기존 지식을 범위 안에서 찾아 관련 노트/원문을 읽고 관계와
근거를 설명한다. 같은 단어나 분류만으로 edge를 만들지 않는다. 독립된 노트도 유용하다.
제한된 검색으로 전역 부재를 단정하지 않는다. AI literacy/독서/일기/프로젝트는 한 사람의
분류 예시이지 강제 전역 체계가 아니다. 정리 깊이와 분류는 나중의 사용자 선호다.

**재사용과 수정이 보여야 한다.** 나중 답에 어떤 정확한 출처/리비전이 어떻게 쓰였는지 알린다.
달라진 것과 유지한 것을 구분한다. 현재는 최대 번호가 아니라 index가 선택한다. 과거 생각을
묻는 경우 이전 버전을 의도적으로 읽고 현재 믿음처럼 쓰지 않는다. Markdown만으로 원문, 현재,
이전, 관련 노트가 이해되어야 하며 Obsidian은 선택이다. 대량 이전, GUI 의존은 없다. 더 읽기 좋은
탐색은71이며 이번 명세가 새 navigation writer를 구현하지는 않는다.

## 수용 기준

가이드/데이터는 이후 설정, 정리 키트, 실제 파일럿의 요구이며 현재 런타임 기능이라는 뜻이 아니다.
의미 품질은 사람이 원문과 결과를 비교해야 한다.

| ID / 사용자 입력 | 남아야 할 것과 확인 방법 | 거부할 실패 | 현재 지원 / 추가할 것 |
| --- | --- | --- | --- |
| K1 “이 성찰 저장해 줘”와 허용 입력/목적지 | 정확한 원문 바이트, 해시, 출처와 별도 정리 리비전. 원문 비교, 노트/현재 포인터 읽기. | 원문 대체, 요약을 원문으로 표시, 미고지 정규화, 범위 밖 저장. | capture/curate/index 존재. 키트가 원문 우선 순서와 경계를 설명. |
| K2 “내 생각의 의미를 정리해 줘” | 이유, 의미 있는 구분, 불확실성과 출처/사용자/해석/추론의 연결. 사람의 원문 대조. | 기계적 재배열, 일반 조언, 확신 강화, 가짜 책/사용자 주장. | 판단은 외부 에이전트. 본문/출처는 지원.70/72의 프롬프트/평가 필요. |
| K3 관련 두 번째 입력과 “이어질까?” | 검색 범위와 읽은 근거, 연결 이유 또는 정당한 비연결. 대상과 리비전 확인. | 단어/분류만 같은 연결, 강제 분류, 발명한 관계나 전역 못 찾음. | recall/search/show와 선택적 relations/graph 존재. 선별 정리는 키트 정책. |
| K4 따로 저장을 요청한 무관한 성찰 | 원문/독립 노트는 남기되 앞 생각과 부당한 다리 없음. 설명과 필요시 graph 확인. | 둘 다 독서 이야기라는 이유로 decoy를 다른 생각의 근거로 사용. | 저장/그래프는 독립성을 표현. 의미 판정은 CLI 기능이 아님. |
| K5 새 성찰로 이전 생각 수정 | 새 source ID/리비전, 과거 해시 불변, 현재 index와 정확한 old/new diff. | 덮어쓰기, 이중 현재 저장소, 상속 검토로 바뀐 내용을 검증했다고 표시. | 불변 리비전/CAS/history/diff 존재. 대상 선택과 변화 설명은 에이전트. |
| K6 새 세션의 답변만 요청 | 명시한 entry/profile/bundle을 읽고 과거/현재를 구분해 새 질문에 정확한 근거로 답함. 저장 권한 없으면 새 지식 쓰기 없음. | 예전 채팅/개인 기록 의존, 일반론, 가짜 기억, 몰래 저장. | 조회는 지원. bootstrap69, kit70, 실제 새 세션72 필요. |
| K7 원문 안 범위 초과 지시 인용 | 인용은 데이터로 보존하되 허용 작업만 수행. 접근/규칙/제공자 변경 없음 확인. | 인용 실행 또는 권한으로 수용. | 안전 경로는 도움. 호스트/에이전트의 권한 준수 필요, 면역 주장 없음. |
| K8 관련 노트를 못 찾음 | 적절한 범위의 다른 단어와 허용 index/list/history 확인, no-match/부분 범위/불확실성 보고. 실제 출력 확인. | 근거 발명, 의미 검색 주장, 이웃 폴더 탐색, 거짓 성공. | exact/prefix/선택 BM25, 진단 존재. 의미 추론, 원문 검색, 자동 세션 기억은 없음. |

고정 제목, 노트 수, 분류, 문체를 강제하지 않는다. 연결은 선택이지만 주장한 연결에는 근거가
필요하다. 좋은 문장이나 높은 검색 점수로 권한/원문/이력의 중대한 실패를 상쇄하지 않는다.

## 새 세션과 개인정보 경계

새 세션에는 명시한 진입 문서 경로, 프로필 경로, 번들 경로와 지금의 목표 및 허용한
읽기/쓰기/입력/출력/제공자 범위가 필요하다.69는 이를 사용자가 볼 수 있는 로컬 파일과 안내로
만들어야 하며 자격 증명, 전역 훅은 두지 않는다. 지금은 기존 workflow/spec 진입점과 승인 경로를
명시해서 전달한다. CLI --profile이나 프로필 자동 발견 기능이 있는 것처럼 말하지 않는다.
설치가 곧 자동 기억은 아니다.

외부 에이전트는 허용된 번들 안 원문을 호스트 파일 도구로 읽을 수 있다. recall은 raw source를
검색하거나 참조를 자동으로 열지 않는다. 클라우드 에이전트는 허용 자료를 제공자에게 보낼 수
있으며 로컬 저장이 종단간 오프라인 추론을 보장하지 않는다. 새 제공자/계정, export, 공유, 범위
확대는 실제 작업 권한을 따르고 노트 속 지시에서 얻지 않는다. 기존 권한의 자동화에 새 인증된
사람 승인이나 명령별 승인 문턱을 만들지 않는다.
