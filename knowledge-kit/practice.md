# Curate knowledge, not just transcripts

**English** | [한국어](practice.ko.md)

Use [START](START.md) plus the filled user-owned profile and today's goal. The
[durable workflow](../workflows/AGENT-WORKFLOW.md) remains authoritative for actual CLI
permissions, requests/CAS and interruptions. This guide tells the agent what good knowledge
work should accomplish. The CLI stores prepared text; it does not supply semantic judgment.

## Understand the request

Classify intent from actual user authority: answer-only, explicit save, justified connection,
revision, or eligible user-enabled trigger. Do not turn an ordinary chat into capture. Confirm
only genuinely missing/branching scope, not every already-authorized command. Preferences
change depth/topics/organization, not source integrity. No compulsory taxonomy or link count.

## Preserve then interpret

For an authorized file, capture that exact file before preparing a note. Compare captured
bytes/digest with the original, including BOM/CRLF. Do not rebuild originals with copy/paste
or save a paraphrase as original. For chat, save the exact exposed text in an authorized
prepared/source file and declare any host export/normalization limits. Never claim access
to unavailable raw channel bytes. Use a new source ID for new material, including revisions.
Keep prepared text outside the bundle. Use a real producer declaration, not fabricated human
review. The user's saved thought can be valuable while remaining uncertain/unverified.

Read the whole permitted source and ask: what is the user trying to understand, why does
it matter, which example or tension carries the meaning, where is the limit? Write a useful
knowledge body, not sentence-shuffling, mechanically extracted bullets or generic advice.
Preserve nuance without treating every sentence as a timeless rule. Mark four different
voices when present: source assertion; user's view/experience; agent interpretation;
unverified inference/open question. Do not invent a book/author claim, stronger certainty,
psychological diagnosis or user's preference. Use [note-body.md](note-body.md) as a flexible
shape, not mandatory filled sections. Let the user inspect/correct the result naturally.

## Find and justify connections

Before a connection, use scoped knowledge reads supported by the current CLI: recall for
indexed current title/body words, search for permitted history, show for exact revisions,
and authorized captured sources for evidence. Read the candidate before linking. State
what relation helps and why that evidence supports it. Same keywords/category or “both are
reading notes” is insufficient. If unrelated or not found, say so with searched scope and
limits; keep the new note independent. No search miss proves global absence. Existing
recall does not search annotation fields/raw originals and is not semantic search.
Recall scans all indexed current notes in the chosen bundle; it has no concept --scope
flag. If that would read excluded payloads, do not call it or full-scan search/list/check.
Use exact authorized show or scope-capable context/graph/health and disclose the limitation.

Prefer a plain Markdown explanation and a justified exact revision link. Typed relations
are optional. If supplied, follow [the actual schema](../docs/graph.md); an unversioned ID
means current pointer while a revision pin is historical evidence, not an automatic update.
Do not force a graph edge, create reciprocal writes or silently copy source-quality claims.

## Save and revise

Use existing capture/curate and optional annotate under the saved request/CAS contract.
Curate must include every relevant source ID, the prepared full body and explicit desired
status/annotations; it does not inherit old metadata/verified silently. Reuse a concept ID
for a revision of that knowledge, not for unrelated material. Read the current pointer
first; preserve originals/older revisions and compare the new result. If meaning changes,
explain both what changed and what remains. Never edit an old revision to add back-links.
Use source/previous/related paths relative to the **final revision**, as [the note template](note-body.md)
shows. New interpretation is not automatically reviewed. No journal/repair is implied.

After a requested write, update only authorized human navigation using [navigation.md](navigation.md).
Then read back current/original/previous links and report meaningful changes and uncertainty,
not a wall of engineering output. Command IDs/retries are the agent's work, not natural
user syntax. Context is optional work handoff, not a substitute for a searchable knowledge
body. Stop on recovery_required; never bypass pending state with a new key.

## Reuse in a fresh session

Use the supplied bootstrap/profile/bundle, not prior chat/private memory. Resolve current
from the managed index; deliberately retrieve old revisions for historical questions.
Answer this user's new question with exact references and explain how prior thought affects
it. Distinguish then versus now and source versus interpretation. If evidence is absent or
partial, say so rather than inventing memory or filling with generic advice. For answer-only,
do not capture the question, save a new note, annotate context or refresh navigation.
Graph/health are structural diagnostics, not truth checks. Explicit judged evaluation can
help measure retrieval later, but cannot replace human assessment of meaning-centered work.
