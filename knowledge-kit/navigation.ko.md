# 현재 저장소를 복제하지 않는 사람용 탐색

[English](navigation.md) | **한국어**

index.md의 `<!-- lkw:current:start -->`와 `<!-- lkw:current:end -->` 사이 CLI 블록만
현재 선택의 정본이다. 마커/항목/줄바꿈을 손으로 바꾸지 않는다. CLI는 이 블록을 관리하고
주변 내용을 보존한다. concepts/ID/rNNNNNN.md와 원문은 수정하지 않는다.

허가한 설정이나 요청한 저장/수정에서만 에이전트가 [landing-fragment.ko.md](landing-fragment.ko.md)의
별도 lsb:knowledge-nav 영역을 루트 index의 CLI 블록 **밖**에 관리할 수 있다. 사람을 위한
읽기 도우미이며 두 번째 현재 registry가 아니다. 리비전 링크는 확인한 관리 블록 시점의
스냅샷이다. 사용 전 현재는 관리 블록에서 다시 확인한다. 다른 CLI/외부 편집으로 오래될 수
있으며 답변만 요청이면 알리고 실제 현재를 읽을 뿐 몰래 탐색을 고치지 않는다.

## 계획, 실행, 확인

1. 실제 탐색 쓰기 권한과 동시 외부 편집 없는 독점 작업 구간을 확보한다. 읽기 권한/답변만은
   부족하다. 불가능하면 허용한 출력 폴더에 제안만 준비하고 번들을 건드리지 않는다.
2. CLI 쓰기 **뒤** index 바이트와 현재 선택을 읽는다. 소유 fragment 한 개만 찾고 사용자
   글/frontmatter/다른 영역을 보존한다. 없으면 명시한 CLI 밖 위치에만 삽입한다. 중복/손상/
   모호한 마커는 중지/초안 사유이지 전체 index 교체나 자동 복구 사유가 아니다.
3. 사람용 제목과 정확한 원문/이전/정당한 관련 링크를 채운다. 제목은 사용자가 바꿀 수 있고
   분류/링크/폴더 이동/별칭을 강제하지 않는다. 지식을 landing에 복제하지 않고 리비전에 둔다.
4. 쓰기 직전 다시 읽어 계획의 전체 index 바이트와 같아야 한다. 다르면 덮어쓰지 않고
   재평가한다. 소유 영역만 교체/허용 삽입하고 CLI 마커를 포함한 밖의 바이트는 정확히 남긴다.
   문서 전체의 줄바꿈/인코딩을 정규화하지 않는다.
5. 다시 읽어 CLI 관리 항목과 무관한 사용자 바이트를 비교하고 실제 상대 파일을 따라간다.
   show/history/diff로 현재/과거/원문의 의미를 확인한다. 깨진 링크/불분명한 출처를 성공으로 보지 않는다.

새 navigation CLI가 아닌 에이전트/파일 도구 절차다. CLI 잠금은 외부 편집을 막지 않으며
재확인만으로 동시 편집이 안전해지거나 트랜잭션/journal이 생기지 않는다. 독점 구간이 필요하다.
잠금/intent를 지우거나 landing으로 복구 가능성을 추정하지 않는다. 운영 workflow를 따른다.
Markdown/텍스트로 탐색할 수 있고 Obsidian은 선택이다. 뷰어 열기가 다른 볼트 읽기나 대량
이전의 허가는 아니다.
